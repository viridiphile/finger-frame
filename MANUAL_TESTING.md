# Iteration 2 manual testing checklist

Run `npm ci` and `npm run dev` in the project directory. Open Vite's printed Local URL in Chrome. Also run `npm run build` and `npm run preview` and repeat the main flow before presenting.

The checkboxes remain uncompleted because real-camera visual checks require a person with a webcam. Automated verification and its limits are recorded in the README.

- [ ] **Full demo:** without permission, watch one 32-second cycle. Confirm normal frame → bowtie with both lobes filtered → A/B interchange → normal with A on the right → return. Original simulated hands remain colored in front of the sketch. Both triangular lobes show scene details with no double-filtered crossing.
- [ ] **Controls/export:** toggle Pencil effect, open Fine-tune the pencil, and adjust all three sliders. Sensitivity changes weak-edge visibility; line intensity changes contour darkness; shading changes tone. Capture a normal frame and a bowtie as PNGs. Check keyboard operation and a narrow/mobile layout.
- [ ] **Camera/mirror:** Start camera, allow access, wait for the tracker. Raise your right hand and confirm it appears on the right. The camera indicator is on and no audio permission is requested.
- [ ] **Normal frame:** in even light, face both palms toward the camera and spread thumbs/index fingers into a window. Confirm `2 / 2 hands`, four markers near the real tips, and fine graphite detail within the outline. The rest of the video remains unchanged.
- [ ] **Bowtie/return:** slowly rotate one hand to reverse its thumb/index orientation relative to the other. Confirm the fixed anatomical connections cross, `Bowtie tracked` appears, and both triangles receive the effect. Return to the original pose and confirm a four-sided region returns. A completely collapsed transition may briefly hold/fade.
- [ ] **Hand interchange:** exchange horizontal hand positions slowly, then exchange back while keeping fingertips visible. Connections should follow the same physical hands rather than flip when the detection array order changes. Repeat with different palms/lighting; record any identity swap under severe overlap.
- [ ] **Short/long occlusion:** establish motion, hide one hand for about 100–150ms, and reveal it. Prediction should be small and bounded, with smooth recovery. Hide it for more than 400ms; the frame/effect disappears and guidance returns. The old mask must not restore a patch of background indefinitely.
- [ ] **Foreground masking:** move palms and individual fingers through each filtered lobe. Hands should stay colored and in front. Inspect fingertips, finger gaps, palm edges and overlapping fingers for sketch leakage or restored-background halos. Repeat with hands closer/farther and tilted sideways; note where landmark approximation fails.
- [ ] **Facial detail/performance:** frame a face, glasses and hair in good light. Check thin contours around eyes and glasses, mild shading and absence of broad blur. Try sensitivity around 40–85%, line intensity around 50–90%, and shading around 10–45%. Observe actual camera FPS and responsiveness; record browser, resolution and lighting. Demo FPS is not a camera benchmark.
- [ ] **Degeneracy/outliers:** pinch tips together, make a tiny lobe, align points nearly on one line, cover both hands and move tips out of view. Geometry should hold/fade with useful guidance, without crashes or huge jumps. An anatomical crossing alone should remain supported.
- [ ] **Cleanup/restart:** Stop clears the preview, disables Capture and switches off the camera indicator. Start again, choose Demo, repeat twice and navigate away. The camera releases each time. Switch tabs and return to confirm reacquisition.
- [ ] **Errors/cancellation:** deny permission and confirm useful guidance plus a working demo. Restore permission. Cancel startup with Stop/Demo; allowing a late request must not reactivate it. Test a busy/unavailable camera and unplug an external camera if available. Block `**/mediapipe/**` in DevTools before starting to verify a tracker failure keeps preview/demo usable; remove the block afterward.

For the classroom fallback, load the demo, disconnect the internet, and confirm the entire cycle, adjustments and Capture still work. Local tracking assets also allow camera startup without a runtime CDN. Keep the Vite/preview terminal running; the application does not install an offline service worker.
