# V3 manual testing checklist

Run `npm ci` and `npm run dev`, open Vite's Local URL in Chrome, and keep the terminal running. Also run `npm run build` / `npm run preview` before presenting.

Checkboxes remain uncompleted because physical-camera visual verification requires a person and webcam. Automated results and their limits are in the README.

- [ ] **Graphite controls:** confirm exactly three sliders: Edge Sensitivity, Line Intensity, Shading Intensity. Each snaps to 0/25/50/75/100 and changes only its own parameter. Defaults are 50/75/50. Test each minimum and all three at 0; a nonuniform scene should retain delicate contours and tone rather than becoming blank. Inspect a real face, eyes, glasses and hair at balanced settings.
- [ ] **Switching:** choose Solarize and Motion Glitch; all Graphite sliders disappear, and neither mode adds sliders. Return to Graphite; the three selections remain. Turn the effect off, switch modes, and turn it on; the selected mode returns without changing Graphite choices.
- [ ] **Solarization:** check charcoal, crimson/cyan and restrained highlights, with recognizable contours and smooth tones. Form a bowtie: A's lobe is warmer and B's cooler. Exchange horizontal hand positions; palette assignment follows anatomy. Shrink one lobe; its valid partner remains processed with the same bias.
- [ ] **Motion Glitch:** hold still for a second; distortion settles. Translate quickly, rotate, expand and contract; channel/slice displacement increases smoothly but stays bounded. Rotate through the angular boundary without a sudden spike. In a bowtie, the lobes distort in opposite directions. Hide a hand and switch effects; no old burst or indefinite feedback should persist.
- [ ] **Demo:** watch the 32-second normal/bowtie/interchange/return cycle in every mode. Both meaningful lobes receive processing, original simulated hands remain in front, and motion drives the glitch without permission. Verify the original scene/design remain recognizable.
- [ ] **Start/mirror:** Start camera, allow access and wait for the local tracker. Raise your right hand; it appears on the right of the mirrored preview. No audio permission is requested.
- [ ] **Geometry:** create a regular frame, rotate one hand into a bowtie, interchange hands and return. Slowly bring fingertips close, pinch one lobe and pass through a near-line pose. Meaningful regions/outline should follow with little flicker; a truly collapsed frame should briefly hold/fade. Separate tips to recover promptly. No shape should expand artificially or freeze indefinitely.
- [ ] **Foreground mask:** move real fingers/palms through each effect/lobe. They should retain original color in front. Inspect fingertip edges, gaps, foreshortened palms and overlap for leakage/halos. Repeat at different distances and note mask limitations.
- [ ] **Loss/performance:** hide one hand for 100–150ms, then for more than 400ms. Prediction is bounded, stale masks disappear, and the frame recovers or fades with guidance. Measure actual camera FPS and responsiveness for each mode; record browser, resolution and lighting. Demo throughput is not a camera benchmark.
- [ ] **Capture/layout:** export a normal and bowtie PNG in each mode. Images match the displayed canvas including outline, without UI controls/badges. Test a narrow window/mobile layout and keyboard controls.
- [ ] **Cleanup/errors:** Stop clears preview and releases the camera; Demo and navigation also release it. Restart twice. Deny permission, test a busy/unavailable device, and cancel a pending request; a late permission result must not reactivate a stopped stream. Test external-camera unplugging and tracker request blocking if possible, then restore settings.

For a classroom fallback, load the demo, disconnect internet, and confirm all three modes, the full cycle, sliders and Capture remain usable. Local model/WASM files also allow camera startup without a runtime CDN. The app has no offline service worker; keep the local server running.
